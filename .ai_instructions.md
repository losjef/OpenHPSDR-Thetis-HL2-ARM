# AI Instruction Profile for OpenHPSDR-Thetis (HL2 Windows ARM64)

This file contains the strict guidelines, workflows, and standards that **Antigravity** (and other AI coding assistants) must adhere to in this repository. 

---

## 1. Core Directives & Best Practices

### A. Zero Assumptions Policy
* **Stop and Ask**: Never make assumptions about design choices, architecture paths, library dependencies, compilers, tools, or target environments. If requirements are ambiguous, ask the user.
* **Explicit Listings**: When presenting plans, explicitly list all underlying assumptions in a dedicated section for user verification.

### B. Plan First, Execute Later
* **Planning Requirement**: For any non-trivial changes (creating/editing source files, modifying build targets, updating dependencies, altering project configs), a plan (`implementation_plan.md`) must be written or updated.
* **User Approval**: Do not modify files until the user has explicitly reviewed and approved the plan in chat.
* **Incremental Phases**: Break plans into granular phases. If execution encounters unexpected issues or compiler errors, pause and revise the plan.

### C. File & Code Linking Protocol (Mandatory)
* **Clickable Links**: You must format all references to files, folders, and code symbols (classes, structs, methods, properties) as clickable links.
* **Format**: Use standard Markdown link syntax with the `file://` scheme and **forward slashes** for all Windows paths.
  * *Example*: `[Thetis.csproj](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/Console/Thetis.csproj)`
  * *Example with line range*: `[channel.c:L110-120](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/wdsp/channel.c#L110-L120)`
* Do NOT wrap the entire link text in backticks (e.g., use `[filename.cs](file://...)`, NOT `[`filename.cs`](file://...)`).

### D. Documentation & Code Integrity
* **Preserve Existing Comments**: Retain all pre-existing comments, docstrings, and license headers unless specifically instructed to modify them.
* **Keep Changes Focused**: Minimize unnecessary code churn; modify only what is necessary to meet the goals.

## 2. Project Architecture & Technical Context

This project is a Windows ARM64 port of the **OpenHPSDR-Thetis** Software Defined Radio (SDR) application, optimized for the **Hermes-Lite 2 (HL2)**.

### A. Tech Stack
* **C# Frontend & GUI**: Main executable ([Thetis (Console)](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/Console/Thetis.csproj)) and helper assemblies ([Midi2Cat](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/Midi2Cat/Midi2Cat.csproj), [RawInput](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/RawInput/RawInput.csproj)) target **.NET 8.0-windows** (WinForms).
* **Native C/C++ Core Libraries**: Performance-critical libraries compiled for ARM64:
  * [wdsp](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/wdsp/wdsp.vcxproj) (core DSP in C)
  * [ChannelMaster](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/ChannelMaster/ChannelMaster.vcxproj) (hardware controller)
  * [cmASIO](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Project%20Files/Source/cmASIO/cmASIO.vcxproj) (ASIO audio API wrapper)
  * **PortAudio** (integrated build target in the solution)
* **Precompiled Native Dependencies**:
  * **FFTW3** (`fftw3-3.dll`): Compiled for ARM64, located in `Project Files/lib/fftw_arm64/`.
  * **Noise Reduction** (`rnnoise.dll`, `specbleach.dll`): Compiled for ARM64, located in `Project Files/lib/NR_Algorithms_arm64/`.

### B. Porting and Compilation Standards
* **Native ARM64 Configuration**: The solution configuration targets `ARM64` (mirroring settings from `x64`).
* **Hardware/Protocol Compliance**: All hardware integration and protocol updates must comply with the [Hermes Lite 2 Hardware Notes](file:///C:/Users/jeffl/Source/repos/github/OpenHPSDR-Thetis-HL2-ARM/Documentation/HL2/Hermes%20Lite%202%20Hardware%20Notes.md) and the official [Hermes-Lite2 GitHub repository](https://github.com/softerhardware/Hermes-Lite2).
* **Intrinsics Compatibility**: Intel SSE-specific compiler intrinsics must be translated or patched for ARM64 using appropriate ARM64 FPCR registers or neon-equivalents where applicable.

### C. 64-bit and P/Invoke Safety
* **Avoid Truncation**: Windows handles (`HWND`, `HMENU`, `HANDLE`), window procedures, and callback parameters are 64-bit values and must target `IntPtr` (or `UIntPtr`) in C# rather than `int` or `uint` to avoid 32-bit truncation errors on 64-bit architectures.
* **Struct Packing & Offsets**: Ensure that marshaled structs are aligned properly, referencing actual Win32 platform layouts.
